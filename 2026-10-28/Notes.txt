Regarding stability of input parameters in the decision for whether a composable is skippable:

Modern Kotlin uses "Strong Skipping Mode" where some parameters that are "unstable" may still
allow the function to be "skippable". (In this case, Compose will just use instance comparison ,
i.e. === instead of equals(), which will force a recomposition if the object reference change,
even if the data inside is identical).
