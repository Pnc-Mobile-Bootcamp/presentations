
hashing algorithm is a function that takes a string as input (any length)
	and returns a fixed-length string as its output
hashing algorithms are not (easily) reversible


that output has a couple of characteristics:
- it is chaotic (any small change in the input string results in a large change in the output)
- chance of collisions is vanishingly small (i.e. two different inputs are extremely unlikely to result in the same output)




when the app sends the request to the OAuth server, 
it sends a callback url (something like: myapp://oauth-callback)


an attacker can register their own callback url with the OAuth server
(i.e. badguyapp://lemme-steal-this)



plain OAuth tokens are bearer-tokens - i.e. whoever has the token has the rights






Encryption
- controlled obfuscation (scrambling up) of some content
- in a way that can be un-done by authorized entities



Encryption functions are not completely one-way functions the way that hashing functions are.
Encryption functions have a key that allows for quick unscrambling (restoration)


Single-key encryption (Symmetric encryption)
- uses a function that has two inputs (value being encrypted, a key) which returns the scrambled value
- if you have the key (number) that was originally used to encrypt, it is trivial to decrypt


Dual-key encryption
- involves a pair of keys (which are mathematically related)
	- we keep one secret, and publish the other
- encryption involves two parameters, the value being encrypted and one of the keys
- decryption uses the other key

e.g. if we want to prove to the world that some content came from us
	- encrypt it with our private key


e.g. if someone wants to securely communicate with me
	- they encrypt it with my public key
